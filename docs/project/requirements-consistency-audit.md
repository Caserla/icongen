# MVP 需求一致性审计

审计日期：2026-08-21
审计范围：已确认决策、PRD、架构、接口文档、共享 Schema、前端页面、Worker、Skill 与数据库迁移。

## 1. 当前唯一产品基线

- 产品是批量 **UI 功能图标生成网站**，不是单个 App Store App Icon 生成器。
- 一次任务包含 1–20 个图标主体；每个主体固定生成 3 个方案并消耗 1 点。
- MVP 只支持 6 组、25 个核心设置，不提供高级模式；原始 266 项只作未来研究参考。
- 平台方统一配置 `gpt-image-2`、`medium`、API Key 和可替换 Skill，普通用户不能配置。
- 只交付 PNG；背景关闭时为透明 RGBA PNG，背景开启时不额外赠送透明副本。
- 新用户赠送 6 点；点数永久有效；首发点数包为 `$2.99/30`、`$6.49/75`、`$12.99/180`。
- 每位用户最多 1 个活动生成任务；提交并扣点后不可主动取消。
- 作品保留 30 天；账户删除宽限期 30 天；资产导出 ZIP 有效 24 小时。
- 英文优先，支持中文切换。

## 2. 已发现并修正的理解偏差

### A1 把完整 266 项实现成 MVP 高级模式

- 偏差：共享代码、接口和部分 PRD 一度把 266 项作为 Advanced settings。
- 正确规则：MVP 只支持 6 组 25 项。
- 已修正：共享包删除完整 taxonomy 运行数据以及 `designMode`、`advancedSelections`；266 项文档仅作参考。

### A2 把产品继续描述为 App Icon 生成器

- 偏差：首页、Metadata、创建页和 Skill 残留单个 App Icon 表述。
- 正确规则：面向 Search、Delete、Add、Back 等批量 UI 功能图标。
- 已修正：网站公开文案、Metadata 和 Skill 已统一为批量 UI function icon。

### A3 继续展示每次生成 4 个方案

- 偏差：首页、创建页、结果页、Mock 数据和 Worker 仍存在 4 个结果。
- 正确规则：每个主体固定 3 个方案。
- 已修正：前端 Mock、共享协议、Worker 和 Skill 均按每主体 3 个方案运行；v1 数据库写入口已撤权。

### A4 价格页使用旧点数包

- 偏差：前端显示 40、120、300 点且未显示已确认价格。
- 正确规则：30 点 `$2.99`、75 点 `$6.49`、180 点 `$12.99`。
- 已修正：价格页展示已确认点数、USD 价格和“1 主体 = 1 点 = 3 方案”。

### A5 文档仍把核心设置称为 taxonomy/设计维度

- 偏差：接口、后台、埋点和 Skill 文档仍可能暗示完整 taxonomy 是首版能力。
- 正确规则：运行时只存在版本化核心设置。
- 已修正：MVP 文档统一改为 `core settings / 核心设置`；参考清单仍保留 taxonomy 名称以标识其来源。

### A6 模型质量说明落后于代码

- 偏差：说明书仍称 `IMAGE_QUALITY` 尚未传入 Provider。
- 正确规则：平台固定 `medium`，代码已经显式传入。
- 已修正：配置说明和 Worker README 已同步。

### A7 页面导航、账户字段和认证状态沿用旧界面

- 偏差：页面规划仍描述访客“创建图标/我的图标”导航、登录态点数导航、四图标工作台、账户创建时间和“账户正常”等已移除内容。
- 正确规则：访客顶部只保留品牌、语言切换和登录；登录态顶部展示“图标生成”“我的图标”、语言切换及用户按钮；用户菜单只保留“个人信息”和“退出登录”。
- 账户页只展示点数余额与充值入口、显示名称、邮箱和验证状态；显示名称保存后同步顶部用户名；删除账户入口暂时隐藏，但独立路由和后端能力保留。
- 认证验证成功统一使用 `/auth/callback` 建立会话后进入 `/auth/verified`，再安全跳转原目标页或 `/create`。
- 已修正：PRD 页面表、前端页面规划、认证 API 手册、认证开发任务和原子级 Excel 计划已同步。

## 4. 范围扩张复核结论

这些内容由此前文档补充产生，并非用户明确要求；在确认前不应优先开发：

### S1 单张 PNG 下载：保留

- 已确认 MVP 同时支持单张 PNG 和选中结果 ZIP 下载。

### S2 删除账户时的数据导出范围：已扩充并确认

- 导出用户资料、订单、点数账本、账单摘要，以及仍有效的 PNG 和 `manifest.json`；排除支付卡数据、密钥、内部完整 Prompt 和管理审计内容。

### S3 运营后台的首版深度：收口

- 不建设完整运营后台，只保留任务查询/安全重试、订单/Webhook 查询、人工调点和操作审计。

## 5. 未发现偏差的已确认规则

- 有背景结果不额外产生透明副本。
- 同一主体可选择多个方案进入 ZIP；每个主体最多一个首选方案并保存到服务端。
- 系统自动重试不额外扣点；主体不足 3 个方案返还 1 点；用户主动重新生成扣 1 点。
- MVP 不支持参考图、SVG、Icon Font、Figma 导出、公开促销码、订阅和团队空间。
- 购买点数和赠送点数永久有效。
- 生成任务提交后不可取消，同一用户最多一个活动任务。
- 网站 UI 视觉风格不受“图标纯色/渐变”等图标资产设置规则限制；两者属于不同规范。

## 6. 后续防偏差机制

- 代码只从 `@icongen/shared` 读取方案数、尺寸、主体上限和 25 项设置，页面不重复定义。
- 新功能先检查 ADR 与本审计基线，再修改 PRD、Schema 和实现。
- CI 搜索并阻止未标记为 legacy/reference 的 `four results`、`App Icon Generator` 和 `advancedSelections`。
- TODO 必须区分“需求已确定”“文档已完成”“代码已实现”，不能用一项勾选代表三者同时完成。
