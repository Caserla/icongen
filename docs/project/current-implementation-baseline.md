# 当前实现基线

更新时间：2026-09-03

本文记录 Bamboo IconGen 当前已经落地的产品与技术事实。发生文档冲突时，优先级依次为：共享 Schema 与数据库迁移、本文、当前架构/API 文档、产品需求、历史审计与参考资料。

## 1. 产品与页面

- 产品支持两种用途：`App 交互图标` 与 `App 插画图标`；协议值仍为 `interaction` 与 `app-icon`，后者是兼容字段名，不代表旧版单一 App Store 图标产品。
- 一次任务支持 1–20 个主体，每个主体固定生成 3 个方案。
- App 交互图标支持线性/面性、主体纯色/多色、主体大小、线性线条粗细、透明/单色/渐变背景、圆角/圆形/方形容器及圆角角度。
- App 插画图标提供 9 种风格；共享目录另保留仅用于交互语境的线性风格，共计 10 个稳定预设。
- App 插画图标的背景模式和形状按主体独立保存；单色和渐变颜色由系统自动生成。
- 输出尺寸为 16、32、48、64、128、256 px，至少选择 1 种、最多 3 种，默认 64、128、256。
- `/icons` 按用途、风格、结构与状态筛选，支持分页和方案缩略图；用途、风格、结构和状态控件先渲染，只有列表区域异步读取当前筛选分页。筛选使用私有 POST 列表接口并在页面内存中缓存，不读取或下发账户全量任务。
- 我的图标列表按当前页批量查询主体、方案和预览资产，并按 Bucket 批量生成短期签名 URL；浏览器不再为每张缩略图执行多层所有权关联查询。
- 同一卡片的 1–3 张方案预览共用加载状态；全部图片成功或失败结算前统一显示 shimmer，结算后整组一次展示，禁止逐张闪现。普通导航进入列表固定回到顶部，从详情返回时在列表完成布局后恢复原滚动位置。
- `/icons/[jobId]` 展示每主体 3 个方案，支持多选、全选/取消全选和 ZIP 下载；不再提供“标记首选”和单图下载按钮。
- `/icons/[jobId]` 的已完成方案支持输入局部修改要求；调整结果先作为草稿预览，手动保存后才生效，并可按版本逐级还原上一次修改。
- 创建页、我的图标页和生成结果页均有独立加载骨架。

## 2. 生成与资产链路

- 当前模型适配器使用 OpenAI-compatible Image2，默认模型 `gpt-image-2`、质量 `high`、母版请求尺寸 `2048x2048`；实际返回母版尺寸以供应商响应为准。
- App 插画图标的 9 种风格均有独立 style spec 和参考图资产；参考图作为视觉风格输入，提示词明确禁止复刻参考板主体或宫格布局。
- Worker 以主体和方案为工作单元并发生成，保存 source、512px preview 和用户选择尺寸的 output PNG。
- PNG 母版保留真实 RGBA/背景语义；普通缩放使用高质量采样和克制锐化，像素艺术使用最近邻。
- 透明背景经过真实 Alpha、假棋盘格和参考板复刻检查。细节调整优先请求原生透明；模型不支持时使用按源图颜色动态选择的色键，并清除与画布边界连通的临时背景、隐藏 RGB、色溢和低 Alpha 暗边。带圆角/圆形背景的 App 插画图标在编辑后逐像素恢复父版本 Alpha，避免新图 Alpha 二次相乘形成黑边或绿边；首次生成链路保持不变。独立透明主体仍强制四角至少 97%、外围边界至少 82% 为 Alpha 0。
- SVG 仅支持 App 交互图标和极简标志。线性 SVG 按 Alpha 轮廓追踪并恢复主体色；彩色 SVG 清理半透明边缘。矢量化失败时跳过 SVG，不影响 PNG 交付。
- ZIP 默认包含所选方案的原始 PNG 母版和任务选择的全部 PNG 尺寸；支持 SVG 时由用户勾选是否追加。
- 方案细节调整只把当前方案作为可编辑源图，不再次发送风格板；编译后的 style spec 继续约束风格。生成后与原图进行感知差异检查，近似原图自动重试，三次无可见变化则失败；原始资产不被覆盖，结果读取和下载自动使用当前生效修订。调整状态、上次输入和失败原因在离开页面后仍可恢复；用户主动还原或丢弃的草稿不会被误报为生成失败。

## 3. 状态与本地执行

- 任务状态：`queued / processing / completed / partial / failed`。
- 方案状态：`queued / processing / completed / failed`。
- 本地开发由 BFF 触发本地 Worker；没有 AWS、SQS 或其他外部队列依赖。
- Worker 使用 Supabase PostgreSQL 读取任务、Supabase Storage 保存私有资产；结果页通过签名 URL 读取。
- 失败方案支持单独重新入队；连续重试由本地启动逻辑合并处理，避免同任务 Worker 启动竞态。
- 细节调整 Worker 每 20 秒续租并检查心跳结果，处理租约为 5 分钟，可覆盖三轮真实模型质量重试；失败、超时和无有效变化均进入可重试闭环。

## 4. 当前开发中

- `feature/variant-detail-editing` 分支已完成方案细节调整代码、Supabase 迁移和真实 Image2 端到端验收。
- 初始版本保持不可变；SVG 失败不影响调整后的 PNG 成功交付。

## 5. 尚未完成或上线前必须确认

- Stripe 生产点数包、Webhook 和真实入账闭环。
- 独立常驻 Worker、部署拓扑、监控、备份和生产密钥管理。
- 作品 30 天清理、账户删除宽限期和用户数据导出完整闭环。
- 正式域名、SMTP、法务主体、隐私/退款政策和首发销售地区。

- 开发计划状态只有经过代码、测试和真实流程验收后才能标记为已完成。
