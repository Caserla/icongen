# 生成结果加载与返回链路回归用例

## 范围

验证生成结果页、细节调整页和返回“我的图标”列表的加载体验。测试使用已登录真实账户和真实生成数据，不创建新的付费生成任务。

## 用例 1：生成结果页首次进入

前置条件：从“我的图标”列表打开一个包含 3 个已完成方案的图标集。

步骤：

1. 点击列表中的图标集。
2. 在结果数据尚未返回时观察页面。
3. 等待三个方案图片完成加载。

预期：

- 数据阶段只显示生成结果页骨架，不出现空白页面。
- 单张图片未完成解码前保持方案图片骨架，不显示渐进扫描或残缺图片。
- 图片完成解码后淡入，最终三张图均具有有效自然尺寸。

## 用例 2：细节调整页面加载

前置条件：方案具有待确认的新图时，页面存在“原图”和“新图”两个版本。

步骤：

1. 点击任一方案的“细节调整”。
2. 观察调整历史请求期间的状态。
3. 等待原图和新图下载、解码完成。

预期：

- 历史请求期间只显示细节调整页面骨架。
- 双图对比区域在两张图片全部就绪前保持统一骨架。
- 两张图片同时显现，不发生一张先出现、另一张随后刷新的情况。
- 任一图片加载失败时结束等待，并在对应位置显示失败提示。

## 用例 3：返回“我的图标”列表

前置条件：先从带筛选条件的列表页进入结果页。

步骤：

1. 记录当前图标类型、风格、状态、页码及滚动位置。
2. 进入任一生成结果页。
3. 点击“返回上一页”。
4. 返回后立即观察列表。

预期：

- URL、筛选条件、页码及滚动位置保持不变。
- 已缓存列表立即恢复，不显示整页列表骨架。
- 后台仅请求发生变化的单个图标集摘要并更新对应卡片。
- 不重新请求整页列表，未变化卡片不闪烁。

## 自动化与真实页面验收记录

- TypeScript、Node 单元测试、ESLint、Next.js 生产构建必须通过。
- 真实页面从扁平活泼列表进入“App 设置图标”结果页，再返回原筛选列表。
- 返回后 250ms 内列表标题和原卡片可见，列表加载骨架不存在。
- 结果页最终 3 张方案图均 `complete=true`、`naturalWidth=512`、`opacity=1`。
- 方案图片区轮询到的可见图片数量只出现 `0 → 3`，没有出现 `1` 或 `2`，确认整组同时显现。
- 真实细节调整页面已验证历史状态加载会闭合；双图同时显现用例需要账户中存在一条“已生成但尚未更新”的待确认草稿，测试过程不额外调用付费图像生成接口制造数据。
