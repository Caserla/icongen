# 产品功能与生产闭环总表（2026-09-04）

## 1. 生产闭环判定标准

某项功能只有在所有适用条件均满足时才能标记为“生产闭环”：

1. 需求、权限、额度、失败语义和数据保留边界已确定。
2. 前端、API、Worker、数据库与存储链路均已实现，服务端不能依赖前端限制保证安全。
3. 扣点、退款、兑换、任务领取等关键写操作具备数据库事务、幂等和并发保护。
4. 正常、加载、空、失败、超时、重试和中英文状态均有明确 UI。
5. 单元/集成/静态安全测试通过；高风险功能在 staging 用真实账户与真实服务验收。
6. 监控、告警、审计、备份恢复、容量阈值和回滚方案可验证。
7. 涉及域名、云平台、邮件、供应商、法务或运营规则的人工配置已经留存验收证据。

状态说明：**生产闭环**表示适用项全部完成；**代码闭环，待生产验收**表示仓库实现与自动化测试存在但真实环境证据未完成；**部分闭环**表示仍缺代码、策略、测试或失败补偿；**暂停/待定**表示当前不得对用户呈现为可用。

## 3. 统计结论

- 功能条目：**40 项**（作品 30 天自动清理已移出当前范围）。
- 当前可称“生产闭环”：**0 项**。原因是尚未完成目标数据库迁移回放、正式域名/SMTP、双账户安全、真实 Worker 故障、监控告警和备份恢复等生产证据。
- “代码闭环，待生产验收”：**37 项**。
- “部分闭环”：**2 项**（运维监控/备份与内容安全）。作品 30 天自动清理已移出当前功能范围。
- “暂停/待定”：**1 项**（在线收款）。
- 明确需要人工参与：**34 项**；无需外部人工、可由研发继续自动完成或回归：**7 项**。

统计用于防止把“代码存在”误报为“生产可用”。人工列为“是”不代表全部工作都要人工编码，而是最终闭环需要账号、云平台、真实费用、运营或法务决策。
