# 我的图标返回导航回归用例

## 目标

验证“我的图标”所有下钻与返回路径都以 URL 为筛选状态的权威来源，并保持图标类型、风格/结构、状态、页码和列表滚动位置一致。禁止出现地址栏与选中态、列表内容互相冲突。

## 状态断言

每次返回列表后必须同时满足：

1. URL 查询参数正确。
2. 对应筛选按钮具有 `aria-current="page"`。
3. 非目标筛选按钮不具有 `aria-current`。
4. 列表项目全部符合当前类型、风格/结构和状态。
5. 翻页场景保留当前页；从结果页返回时恢复离开前的滚动位置。
6. 静态筛选区可以先显示，列表加载状态不得把筛选状态重置成服务端旧缓存。

## 回归原因与防复发约束

原问题使用 `window.history.replaceState` 只改变可见 URL，未同步 Next.js App Router 的路由树。框架返回缓存页面时，地址栏可以是黏土 3D，但组件仍恢复扁平活泼状态。

修复约束：

- 筛选和翻页使用 `router.replace(..., { scroll: false })` 同步 App Router。
- 筛选按钮先更新客户端 reducer，保证即时交互反馈。
- 进入结果页时，返回地址必须由当前 reducer 状态和当前页显式构造，不读取可能滞后的 `window.location`。
- 返回结果只刷新发生变化的列表项目，不重置整页筛选状态。
