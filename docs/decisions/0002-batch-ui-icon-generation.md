# ADR-0002：批量 UI 图标生成范围

- 状态：已确认
- 日期：2026-08-20
- 替代：ADR-0001 中“单个 Icon、4 个方案”的决策

## 决策

- 产品核心从单个 App Icon 改为一批 UI 图标。
- 一次任务允许提交多个有序图标主体。
- 同一批次共享颜色、背景、核心设计设置和尺寸，主体可保留个别颜色覆盖能力。
- 每个主体固定生成 3 个方案。
- 核心页面分为图标设计 `/create` 与结果预览下载 `/icons/[jobId]` 两个阶段。
- 用户选择任意成功方案后下载 PNG ZIP；未选中时禁止下载。
- 背景关闭时目标输出为透明背景 RGBA PNG，背景开启时使用用户设置的背景。
- 分类附件作为生成页设置项来源，整理为版本化 taxonomy 后由前后端使用。

## 影响

- 生成数据模型由固定 4 个 job result 改为 job → subjects → 3 variants → size assets。
- 计费按主体数量计算：1 个主体固定包含 3 个方案，消耗 1 点。
- 队列、进度、失败返还、存储路径和后台查询需要支持子任务粒度。
- 所有旧文档、接口和代码中的固定 `slot 1..4` 都需要迁移。

## 已确认的补充规则

- 每次任务最多 20 个主体。
- 原始分类附件已校对为 10 个一级分类和 266 个二级分类；根据 ADR-0003，它只作为未来研究参考，MVP 仅支持 6 组 25 个核心选项。
- 同一主体最终不足 3 个方案时返还该主体 1 点，自动重试不额外计费。
