# 图片生成业务模块需求

文档版本：2.0
产品阶段：MVP
页面阶段：图标设计；生成结果预览与下载

## 1. 模块目标

本模块通过结构化设置引导用户描述多个 UI 图标，并将选择结果转换为可验证、可追踪的生成规格。平台后端使用可替换 Icon Skill 编译提示词，再调用平台方配置的图片模型。普通用户不接触模型、API Key、Skill 或内部提示词模板。

## 2. 页面结构

### 2.1 阶段一：图标设计 `/create`

建议桌面端采用左侧主表单、右侧固定设计摘要；移动端改为单列步骤式表单。

表单分为四个步骤：

1. 图标主体。
2. 颜色与背景。
3. 6 组核心设置。
4. 尺寸、费用与提交确认。

右侧设计摘要实时展示主体数量、颜色、背景、已选维度、尺寸、预计点数和自然语言语义预览。该预览用于帮助用户理解，不等于发送给模型的最终提示词。

### 2.2 阶段二：结果预览与下载 `/icons/[jobId]`

同一路由承载排队、生成中、部分成功、完成和失败状态。页面刷新后从服务端恢复，不依赖创建页内存。

## 3. 图标设计阶段功能需求

### GEN-001 多图标主体输入 — P0

用户可新增、删除、排序多个图标主体。每行包含：

- `name`：短名称，例如 `Search`、`Delete`，必填，1–40 字符。
- `description`：主体语义和动作，例如“放大镜，表示查找内容”，必填，2–300 字符。
- 可选的主体颜色覆盖；未设置时继承批次默认主体颜色。

交互规则：

- 默认提供 1 行，至少保留 1 个主体。
- 支持逐行添加以及粘贴多行快速创建；批量粘贴先预览解析结果再确认。
- MVP 每次任务最多 20 个主体，限制由服务端配置并返回，不能仅前端写死。
- 同名允许提交但给予警告，导出文件名自动追加序号。
- 删除已填写行需二次确认或提供可撤销 Toast。
- 列表拖拽或上下移动后，结果页保持相同顺序。

验收标准：添加“生成、返回、新增、查找、删除”后能形成 5 个有序主体；刷新草稿时输入仍可恢复；超限不能提交。

### GEN-002 主体颜色 — P0

批次默认颜色提供 `Solid` 和 `Gradient` 两种模式。

纯色字段：

- 颜色选择器。
- Hex 输入，格式 `#RRGGBB`。

渐变字段：

- 起始颜色和结束颜色；MVP 固定 2 个颜色节点。
- 渐变方向：上→下、下→上、左→右、右→左、左上→右下、右上→左下、径向。
- 小型实时色块预览。

规则：切换模式时保留该模式最后一次合法值；接口只提交当前模式字段。文字描述中的颜色与设置冲突时，以结构化颜色设置为准，并在摘要中提示。

### GEN-003 背景开关与背景颜色 — P0

用户选择是否需要图标背景：

- `No`：隐藏 Background Container 设置和背景颜色；提交 `background.enabled=false`；输出目标为透明背景 PNG。
- `Yes`：显示 Background Container 分类、背景纯色/渐变设置和预览。

背景颜色支持与主体颜色相同的纯色、双节点渐变和方向设置。前端计算主体与背景的基本对比度风险并给出提醒，但不阻止用户提交。

关闭背景后，先前的背景设置可保留在本地草稿方便恢复，但不得发送为生效参数。重新开启时恢复最近一次合法设置。

有背景任务只交付带背景版本，不额外赠送透明背景副本；用户需要透明结果时必须在设计阶段关闭背景。

### GEN-004 6 组 25 个核心设置 — P0

MVP 只提供以下设置，不提供高级模式：

| 设置组 | 选项 |
| --- | --- |
| 图形结构 | Outline、Filled、Line + Fill、Duotone |
| 视觉气质 | Neutral、Rounded、Bold、Playful、Technical |
| 线条粗细 | Light、Regular、Medium、Bold |
| 配色方式 | Monochrome、Two-tone、Multicolor、Gradient |
| 背景容器 | None、Circle、Square、Rounded Square、Pill |
| 细节程度 | Auto、Minimal、Standard |

交互与数据要求：

- 每组单选，页面直接展示全部 25 个选项，不提供跨分类搜索或 `More`。
- 每个选项提供稳定 ID、中英文标签和简短说明；前后端从共享配置读取。
- 背景关闭时容器固定为 `None`；背景开启时必须选择其他容器。
- Skill 内部固定 UI Glyph、正视正交、Flat、无阴影和批次一致性，不作为用户设置展示。
- 原始 10 维度、266 项分类仅作为未来研究参考，不进入 MVP 请求、后端校验或 Skill 输入。

### GEN-005 尺寸设置 — P0

首发开放全部常用 PNG 尺寸：`16、20、24、32、48、64、128、256、512、1024 px`。默认选择 `24、48、128 px`，用户至少选择一个。

业务规则：

- 图片模型生成高分辨率母版，服务端统一裁切、缩放和质量检查后导出所选尺寸。
- 所有输出保持正方形；透明背景输出为 RGBA PNG。
- 当选择 16/20/24px 且 Complexity 过高时显示“细节可能丢失”的提示。
- 尺寸不改变模型/API 配置，只改变生成约束和派生文件。

### GEN-006 草稿与表单校验 — P0

- 未提交设计保存在本地草稿；登录用户后续可扩展服务端草稿。
- 所有字段按步骤校验，提交时滚动并聚焦第一个错误。
- 修改会隐藏某些字段的父设置时，隐藏字段不参与有效载荷。
- 页面离开且有未保存修改时提示用户。
- 中英文切换不改变已选稳定 ID 或用户原始输入。

### GEN-007 提交生成 — P0

用户点击 Generate 后：

1. 前端生成幂等键并提交标准化请求。
2. 服务端验证身份、账户状态、核心设置版本、主体数量、选项规则、点数和账户级并发限制。
3. 服务端重新计算价格，在事务内扣点、创建父任务和主体子项。
4. 成功后立即跳转 `/icons/[jobId]`。
5. 点数不足返回购买入口并保留草稿。

并发与取消规则：

- 每个用户最多同时存在 1 个 `queued` 或 `processing` 任务。
- 已有活动任务时，用户仍可编辑并保存下一份本地草稿，但提交接口返回 `ACTIVE_JOB_LIMIT_REACHED` 和当前任务 ID。
- Generate 提交成功并完成扣点后不提供用户取消入口；系统继续处理直至完成、部分成功或最终失败。
- 系统失败、自动重试和点数返还继续遵循统一计费规则，不因页面关闭或用户退出登录改变。

请求示例：

```json
{
  "idempotencyKey": "uuid",
  "settingsVersion": "core-settings-2026-08-20.1",
  "subjects": [
    { "clientId": "s1", "name": "Search", "description": "Magnifier for finding content" },
    { "clientId": "s2", "name": "Delete", "description": "Trash can for deleting an item" }
  ],
  "subjectColor": {
    "mode": "gradient",
    "colors": ["#6D4AFF", "#B7F34A"],
    "direction": "top-left-to-bottom-right"
  },
  "background": {
    "enabled": false
  },
  "coreSettings": {
    "graphicStructure": "filled",
    "visualTone": "rounded",
    "strokeWeight": "regular",
    "colorMode": "gradient",
    "backgroundContainer": "none",
    "detailLevel": "auto"
  },
  "sizes": [24, 48, 128]
}
```

## 4. 生成结果阶段功能需求

### GEN-008 异步进度 — P0

页面展示：

- 0–100 的任务百分比。
- 当前阶段文本：排队、准备设计规格、生成图标、处理 PNG、保存结果、完成。
- 已完成主体数 / 总主体数。
- 可用时显示正在处理的主体名称。

进度必须来自后端任务单元状态，不伪造模型内部进度。推荐计算方式：

```text
总工作单元 = 主体数 × 3 个方案
生成阶段进度 = 已完成或最终失败的工作单元 / 总工作单元
再按“排队 5%、规格编译 5%、生成 80%、后处理与保存 10%”映射
```

接口可使用轮询、SSE 或实时订阅；MVP 默认每 2 秒轮询，页面后台时降低频率。网络中断后自动恢复，超过阈值显示手动重试。

### GEN-009 Skill 与模型处理 — P0

后端处理顺序：

1. 读取任务快照和对应核心设置版本。
2. 将多主体、颜色、背景、维度和尺寸规范化为 `GenerationSpec`。
3. Icon Skill 为每个主体编译 3 个语义一致但构图细节有差异的方案提示词。
4. Provider Adapter 调用平台方配置的模型。
5. 校验文件类型、尺寸、透明通道和基本可用性。
6. 保存母版与派生 PNG，写入结果、版本和成本元数据。

不允许把用户输入作为系统指令执行；用户文本只作为图标语义字段。Skill 必须加入禁止水印、无关文字、现有品牌标识和受保护角色等平台约束。

内容政策：

- 允许生成通用功能与产品语义图标，不承诺复刻知名品牌 Logo、第三方商标或受保护角色。
- 对违法、仿冒、侵权导向和受保护角色请求执行提交前检查；生成结果仍需进行后置安全检查。
- 被拦截请求不得扣点或创建生成任务；MVP 通过支持邮箱处理误判申诉。

### GEN-010 结果网格 — P0

- 一个主体独占一行，左侧显示名称、描述和状态，右侧固定展示 3 个方案卡片。
- 桌面端 3 列；移动端在同一主体分组内横向滚动或纵向堆叠，不混入下一主体。
- 卡片包含预览、方案编号、生成状态、选择框、首选标记、单图放大和重试状态。
- 用户可以选择多个方案进入 ZIP；每个主体最多标记一个首选，首选默认自动被选中。
- 首选方案保存到服务端，登录用户刷新或跨设备访问时能够恢复。
- 同一主体允许同时选择多个方案进入 ZIP。
- 失败方案保留占位和错误说明，不破坏同一主体的其他成功方案。
- 部分成功时允许下载已有结果，并明确退款或补偿状态。

### GEN-011 选择与 ZIP 下载 — P0

- 底部固定操作栏显示 `Selected X`、全选可用结果、清除选择和下载按钮。
- 未选择任何方案时按钮禁用；若仍触发请求，前后端都返回 `NO_RESULTS_SELECTED`。
- 服务端验证任务所有权、结果归属、文件状态和允许尺寸，创建临时 ZIP。
- ZIP 文件名：`bamboo-icongen-{jobId}-{yyyyMMdd-HHmm}.zip`。
- ZIP 目录建议：`{subject-slug}/{subject-slug}-v{1..3}-{size}px.png`，并附 `manifest.json` 记录设计设置和版本，不包含内部完整提示词或密钥。
- 下载 URL 短时有效；重复点击可复用未过期归档，不重复打包。

## 5. API 需求

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/generation/settings` | 获取 6 组核心设置和版本 |
| `GET` | `/api/generation/config` | 获取主体上限、尺寸、3 方案数和价格摘要 |
| `POST` | `/api/generation/jobs` | 校验、扣点并创建批量任务 |
| `GET` | `/api/generation/jobs/{jobId}` | 获取进度、主体和结果 |
| `POST` | `/api/generation/jobs/{jobId}/retry` | 对允许的失败单元安全重试 |
| `POST` | `/api/generation/jobs/{jobId}/downloads` | 根据结果 ID 与尺寸创建 ZIP |

任务查询响应至少包含：`status`、`progress.percent`、`progress.phase`、`completedSubjects`、`totalSubjects`、`subjects[]`、每主体 `variants[3]`、选择可用性、点数扣除/返还摘要。

## 6. 数据模型调整

- `generation_jobs`：父任务、用户、状态、进度、settings/skill/model/price 版本、点数摘要。
- `generation_subjects`：每个主体的名称、描述、顺序和颜色覆盖。
- `generation_variants`：每主体 3 条，保存 slot、状态、母版和元数据。
- `generation_assets`：每个 variant 的尺寸、对象路径、宽高、透明通道和校验状态。
- `generation_job_specs`：提交时的不可变结构化规格快照。
- `download_archives`：选择结果哈希、ZIP 路径、过期时间和创建状态。

唯一性建议：`(subject_id, slot)`；对象路径不得继续只使用 `{jobId}/result-{slot}.png`，应包含 `subjectId`。

## 7. 错误状态

| 错误码 | 场景 | 前端处理 |
| --- | --- | --- |
| `VALIDATION_ERROR` | 主体、颜色、尺寸或选择非法 | 定位字段并保留草稿 |
| `SETTINGS_VERSION_EXPIRED` | 提交设置版本已下线 | 刷新核心设置，标记需要重新确认的变化 |
| `INSUFFICIENT_CREDITS` | 服务端余额不足 | 打开点数包并保留设计 |
| `ACTIVE_JOB_LIMIT_REACHED` | 当前账户已有生成中的任务 | 保留草稿并跳转或打开当前任务 |
| `CONTENT_POLICY_BLOCKED` | 主体描述违反内容政策 | 标记对应主体，不扣点并提供支持入口 |
| `GENERATION_QUEUE_FAILED` | 创建成功但投递异常 | 显示安全重试，不重复扣点 |
| `GENERATION_PARTIAL` | 部分方案最终失败 | 展示已有结果和补偿说明 |
| `NO_RESULTS_SELECTED` | 未选结果下载 | 聚焦选择区并提示至少选择一个 |
| `DOWNLOAD_NOT_READY` | 资产未完成或 ZIP 处理中 | 显示处理中并轮询 |
| `RESOURCE_FORBIDDEN` | 非资源所有者 | 返回 403，不暴露资源是否存在 |

## 8. 埋点与验收

关键事件：`generation_design_started`、`subject_added`、`core_setting_selected`、`background_toggled`、`generation_submitted`、`generation_completed`、`variant_selected`、`primary_variant_marked`、`zip_download_requested`、`zip_download_completed`。

P0 验收场景：

1. 5 个主体、透明背景、纯色、合法维度和 3 个尺寸能够提交并生成 15 个方案槽位。
2. 背景关闭时背景分类与颜色隐藏，接口不携带生效背景值。
3. 渐变模式必须有 2 个合法颜色和方向。
4. 进度刷新后不倒退，断网恢复后继续。
5. 每个主体始终独立成组显示 3 个方案槽位。
6. 选择跨主体的结果能够得到只含选中 PNG/尺寸的 ZIP。
7. 空选择、越权结果 ID、过期设置版本和点数不足均被前后端拒绝。
8. 任务和结果能追溯到核心设置、Skill、模型和价格版本。
9. 用户存在活动任务时不能提交第二个任务，但本地草稿仍保留。
10. 已扣点任务无用户取消入口；关闭页面后任务继续运行。
11. 被内容政策拦截的请求不创建任务、不扣点，并返回可定位到主体的错误。
