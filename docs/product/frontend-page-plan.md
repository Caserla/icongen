# Bamboo IconGen 前端页面规划

文档版本：1.1（2026-08-21 同步当前前端实现）
依据：PRD 2.0、六大业务模块、认证与账户需求、图片生成设置项体系
界面语言：英文与中文切换
设计方向：暖白、深墨色、亮紫、酸性绿、编辑感标题、圆角卡片、柔和光晕和克制阴影

## 1. 页面规划目标

前端需要支持用户从了解产品到付费、生成、查看和下载的完整闭环，并提供一个最小运营工具页。页面按“公开营销、认证、用户工作台、支付、最小运营支持”五个区域组织。

```text
公开营销
  首页 → 价格页 → 注册/登录

用户工作台
  图标设计 → 生成进度与结果 → 选择方案 → 下载 PNG ZIP
      ↘ 点数不足 → 购买点数 → 支付结果 → 返回创建

账户管理
  个人信息 → 修改显示名称 / 查看邮箱验证状态 / 充值

最小运营支持
  单页工具 → 任务重试 / 订单查询 / 人工调点 / 审计
```

## 3. 业务模块一：用户信息

### 3.1 账户中心 `/account`

页面目标：让用户集中查看和修改必要的个人信息，并从点数余额卡片进入充值流程。

主要区域：

- 点数余额卡片和购买入口。
- 登录邮箱与验证状态。
- 显示名称查看和编辑；保存成功后顶部导航昵称立即同步。

页面状态：

- Skeleton 加载。
- 正常账户。
- 受限账户：说明限制原因和联系支持入口。
- 删除处理中：锁定新增业务操作。
- 账户读取失败：错误面板和重试。
- 昵称保存中、成功、校验失败和网络失败。

接口依赖：

- `GET /api/account`
- `PATCH /api/account/profile`
- `POST /api/auth/sign-out`

当前状态：已接入真实账户查询和资料修改接口；页面当前只展示点数余额、充值入口、显示名称、邮箱及验证状态。加入时间、账户正常提示、使用统计和删除账户入口已按当前界面决策移除或隐藏。

### 3.2 删除账户 `/account/delete`

页面目标：完成高风险操作的影响告知、重新认证和二次确认。

主要区域：

- 删除影响列表：账户访问、作品、剩余点数。
- 当前密码输入。
- 输入大写 `DELETE`。
- 处理中任务冲突提示。
- 最终提交和返回账户页。

删除申请成功后切换为 30 天宽限状态：

- 展示正式删除日期和剩余天数。
- 提供“Download my data / 下载我的数据”按钮。
- 展示异步打包进度、失败重试和 24 小时下载链接有效期。
- 允许在宽限期内撤销删除。
- 禁止生成和支付，但保留账户、历史和数据下载访问权限。

接口依赖：`POST /api/account/delete-request`、`POST /api/account/data-export`、`GET /api/account/data-export/[exportId]`。

当前状态：独立页面、申请删除、30 天倒计时与撤销交互已建立，但入口暂不在个人信息页展示；数据导出完整闭环仍待完成。

## 4. 业务模块二：登录与账户

### 4.1 登录 `/auth/sign-in`

页面目标：让已注册用户快速、安全地进入工作台。

主要区域：

- 左侧展示 Bamboo IconGen 的 UI 图标生成价值说明。
- 邮箱、密码、显示密码。
- 忘记密码入口。
- 登录按钮和加载状态。
- 注册入口。
- 无效回调、未验证邮箱、错误凭据和限流提示。

接口依赖：`POST /api/auth/sign-in`。

当前状态：视觉、登录接口、安全 `next` 回跳、密码显隐和双语文案已完成；主文案统一为“生成一套真正你需要的 UI 图标库”，辅助提示为“登录后，开始创作你的图标吧。”；仍需补齐未验证邮箱分流、细分错误码和限流状态。

### 4.2 注册 `/auth/sign-up`

主要区域：邮箱、密码、确认密码、密码规则、服务条款和隐私政策勾选、注册按钮、登录入口。

需要验证邮箱时在注册页展示检查邮箱提示，不得直接进入创建页；用户点击邮件链接后由 `/auth/callback` 建立会话并进入 `/auth/verified`。

接口依赖：`POST /api/auth/sign-up`。

当前状态：注册页、字段校验、条款确认、密码显隐、提交状态和接口调用已完成；验证邮件重发闭环仍待完善。

### 4.3 邮箱验证 `/auth/verified`

验证链接由 `/auth/callback` 建立会话后跳转本页。本页明确展示验证成功状态，自动保留登录态，并安全跳转原目标页面或 `/create`。注册后的“检查邮箱”和重发验证能力仍需补齐独立页面状态。

接口依赖：`POST /api/auth/resend-verification`。

### 4.4 忘记和重置密码

- `/auth/forgot-password`：提交邮箱并显示不泄露账户存在性的通用成功提示。
- `/auth/reset-password`：新密码、确认密码、规则提示、链接失效状态。

接口依赖：

- `POST /api/auth/forgot-password`
- `POST /api/auth/reset-password`

### 4.5 全局会话体验

- 未登录访问受保护页面，跳转登录并保留安全的 `next`。
- 会话过期时显示提示，再进入登录页。
- 已登录用户访问登录/注册页，跳转 `/create`。
- 顶部导航展示“图标生成”“我的图标”、语言切换、默认头像与用户名；账户菜单只保留“个人信息”和“退出登录”。
- 点击菜单外区域或按 `Esc` 自动关闭，展开箭头带旋转动画。

## 5. 业务模块三：图片生成

### 5.1 阶段一：图标设计 `/create`

页面目标：通过分步设置收集一批 UI 图标主体和统一设计方向，并创建每主体 3 个方案的任务。

页面四个步骤：

- 图标主体：新增、删除、排序和批量粘贴多个主体。
- 颜色与背景：主体纯色/渐变；背景开关、背景容器和背景纯色/渐变。
- 核心设置：6 组、25 个固定选项，全部直接展示，不提供高级模式。
- 尺寸与确认：常用 PNG 尺寸、设计摘要、语义预览和预计点数。

桌面端左侧为主表单，右侧为固定设计摘要；移动端改为单列 Accordion/步骤式体验。详细字段和规则见 [图片生成模块需求](./icon-generation-requirements.md)。

页面状态：

- 默认输入。
- 主体为空、数量超限或描述非法。
- 渐变缺少颜色或方向。
- 核心设置组合非法或版本过期。
- 点数不足：显示购买点数 CTA。
- 提交中：禁止重复提交。
- 创建成功：跳转 `/icons/[jobId]`。
- 队列投递异常：提供安全重试。
- 邮箱未验证或账户受限。

接口依赖：`POST /api/generation/jobs`。

当前状态：视觉与本地输入验证已完成，真实任务创建已连接 Supabase，后台生成执行仍待联调。

### 5.2 阶段二：生成结果预览与下载 `/icons/[jobId]`

生成过程不单独建立新路由，统一由 `/icons/[jobId]` 展示。

状态和布局包括：

- `queued`：任务正在排队。
- `processing`：展示后端计算的百分比、阶段文本、完成主体数和方案槽位 Skeleton。
- `completed`：每个主体独占一行，一行展示 3 个方案。
- `partial`：展示已有方案、失败单元和点数补偿摘要。
- `failed`：说明点数返还并提供安全重试或复制设计入口。
- 底部固定选择操作栏：已选数量、全选、清除和 `Download selected as ZIP`。

前端通过轮询或实时订阅更新任务状态；百分比来自后端工作单元，不能伪造模型内部进度。用户离开页面后任务继续执行。

## 6. 业务模块四：作品与下载

### 6.1 我的图标 `/icons`

页面目标：帮助用户返回历史任务，快速识别任务状态和内容。

主要区域：

- 状态筛选：全部、生成中、已完成、失败。
- 任务卡片：主体摘要、主体数量、计划/成功方案数、创建时间、状态和结果缩略图。
- 分页或加载更多。
- 空状态和创建第一个图标 CTA。
- 加载失败和重试。

当前状态：已有双语列表骨架和模拟数据，筛选、分页及真实接口未实现。

### 6.2 任务详情 `/icons/[jobId]`

页面目标：呈现一次批量任务中每个主体的 3 个方案，并支持选择、首选标记、单张和 ZIP 下载。

完成状态页面包括：

- 原始主体列表、颜色、背景、核心设置和尺寸摘要。
- 任务状态和创建时间。
- 每主体一行、每行 3 张独立方案卡片。
- 大图预览。
- 单张 `Download PNG` 和选中结果 `Download ZIP`。
- 再次生成或使用同一描述创建新任务。

安全规则：

- 只允许资源所有者访问。
- 图片地址使用短时签名 URL。
- 下载按钮必须对应真实 PNG，不依赖浏览器截图。

接口规划：

- `GET /api/generation/jobs/[jobId]`
- `POST /api/generation/variants/[variantId]/download-url`
- `POST /api/generation/jobs/[jobId]/downloads`

当前状态：页面骨架和模拟数据存在；详情查询、轮询、大图预览与签名下载接口未实现。

## 7. 业务模块五：点数与 Stripe 支付

### 7.1 价格页 `/pricing`

页面目标：解释点数模式并让用户选择合适点数包。

主要区域：

- 点数如何消费。
- Starter、Maker、Studio 点数包。
- 每包价格、点数和预计可生成任务数。
- 推荐套餐。
- 支付、安全和退款说明。
- 常见问题。

当前状态：双语视觉骨架已完成，价格和 Checkout 尚未接入真实配置。

### 7.2 Stripe 跳转与结果页 `/billing/result`

流程：

1. 用户选择点数包。
2. 前端调用 `POST /api/billing/checkout`。
3. 跳转 Stripe Checkout。
4. Stripe 返回 `/billing/result?session_id=...`。
5. 页面查询订单状态，不以 URL 返回结果直接增加点数。
6. Webhook 入账后刷新余额。

结果页状态：支付确认中、支付成功、支付取消、支付失败、入账延迟。

### 7.3 点数账本 `/account/credits` — P1

展示购买、生成扣点、失败退款和人工调整记录，不提供用户直接修改能力。

## 8. 业务模块六：最小运营支持

只建设 `/admin/operations` 一个受保护页面，不建设完整运营后台。

- 任务区：按 job ID 或邮箱查询任务，查看主体、variant、错误和资金摘要，安全重试失败单元。
- 支付区：按订单、Stripe Session/Event 查询入账状态。
- 点数区：填写原因和工单号后人工调点。
- 审计区：查看以上写操作产生的审计编号和记录。
- 不提供数据概览、用户管理、复杂筛选、设置编辑器、模型管理和自动退款工作台。

## 9. 跨模块公共页面状态

所有核心页面必须覆盖：

- 首次加载 Skeleton。
- 空状态。
- 网络或服务器错误。
- 无权限 `403`。
- 会话过期 `401`。
- 账户受限。
- 删除处理中。
- 操作提交中和防重复提交。
- 成功反馈与可恢复失败。
- 中文和英文长文案适配。
- 移动端 390px、桌面端和 200% 文字缩放。

## 10. 全局导航规划

### 公开导航

- Logo：首页。
- Sign in / 登录。
- EN / 中文切换。

访客导航不展示“创建图标”或“我的图标”；访客通过首页主 CTA、受保护路由或价格购买动作进入登录流程。

### 登录后导航

- Icon generator / 图标生成。
- My Icons / 我的图标。
- EN / 中文切换。
- 用户按钮：默认头像、用户名和展开箭头；不在顶部展示邮箱。
- 账户菜单：个人信息、退出登录。

### 移动端

- 顶部保留 Logo、语言切换和账户入口。
- “图标生成”“我的图标”在桌面顶部横向展示；移动端采用紧凑布局，不恢复旧的四图标导航。
- 主要 CTA 保持至少 44px 点击区域。

## 11. 双语规划

- 默认语言为英文，用户选择中文后本地保存偏好。
- 所有普通用户页面、表单、状态、错误和邮件均需要中英文版本。
- 模型提示词仍由平台 Skill 编译，不因页面语言直接改变内部安全约束。
- 用户输入保持原文，不自动翻译后覆盖。
- 日期、数字和金额使用当前语言区域格式化。
- URL 首版不增加 `/en`、`/zh` 前缀；后续需要 SEO 多语言时再引入语言路由。

## 12. 页面开发优先级

### Sprint 1：认证闭环

- 登录页面完善。
- 注册页面。
- 邮箱验证页面。
- 忘记和重置密码页面。
- 登录态导航和退出。

### Sprint 2：生成闭环

- 创建页接入真实任务接口。
- 任务详情轮询。
- 真实进度、每主体 3 个方案和部分失败退款提示。
- 历史列表接入真实数据。
- PNG 签名下载和选中结果 ZIP。

### Sprint 3：支付闭环

- 价格和点数包真实配置。
- Stripe Checkout。
- 支付结果页。
- 全局余额刷新。

### Sprint 4：账户和最小运营支持

- 账户真实数据和昵称修改。
- 删除账户确认页。
- `/admin/operations` 单页工具。
- 任务重试、订单/Webhook 查询、人工调点和审计。

## 14. MVP 前端完成标准

- 访客可以浏览首页和价格页，并完成注册、验证、登录和密码恢复。
- 已验证用户可以购买点数、创建多主体任务、等待生成、按主体查看 3 个方案并下载选中 PNG ZIP。
- 页面刷新和重新进入后仍能看到正确任务状态和余额。
- 失败任务明确说明点数返还结果。
- 用户只能访问自己的任务和下载链接。
- 全部用户页面支持英文和中文切换。
- 桌面和移动端核心流程通过端到端测试。
- 加载、空、错误、无权限和账户受限状态齐全。
