# 用户信息、登录与账户模块需求

文档版本：1.0  
产品阶段：MVP  
界面语言：英文优先，支持中英文切换
身份服务：Supabase Auth

## 1. 范围与目标

本需求覆盖两个业务模块：

- 登录与账户：注册、验证、登录、会话、退出、密码重置和受保护页面。


## 2. MVP 产品决策

- 首版使用邮箱和密码注册、登录。
- 注册后必须完成邮箱验证，才能创建生成任务或购买点数。
- Magic Link、Google、Apple 等第三方登录暂不进入 MVP。
- 新用户完成注册资料初始化后赠送 6 点体验点数，可生成 6 个图标主体、共 18 个方案；数值仍通过服务端版本化配置管理。
- 体验点数只能发放一次，必须写入点数账本并通过用户 ID/账本业务键保证幂等。
- 用户邮箱首版不可在账户页直接修改。
- 昵称为可选字段，长度 1–40 个字符。
- 订单、支付和审计信息的最终保留期限需要在上线前完成合规确认。

## 3. 用户角色

| 角色 | 权限 |
| --- | --- |
| 访客 | 访问营销页、价格页、注册和登录页 |
| 未验证用户 | 查看验证提示、重发验证邮件、退出登录 |
| 已验证用户 | 使用生成、作品、支付和账户功能 |
| 被限制用户 | 登录并查看限制说明，不允许创建生成任务或支付 |
| 管理员 | 通过运营后台查看和处理用户状态，不在本模块提供前台入口 |

## 4. 页面与路由

| 页面 | 路由 | 访问规则 |
| --- | --- | --- |
| 登录 | `/auth/sign-in` | 访客；已登录用户跳转 `/create` |
| 注册 | `/auth/sign-up` | 访客；已登录用户跳转 `/create` |
| 检查邮箱提示 | `/auth/sign-up` 页面内状态 | 未验证用户 |
| 验证成功 | `/auth/verified` | Auth 回调已建立会话的用户 |
| 忘记密码 | `/auth/forgot-password` | 访客 |
| 重置密码 | `/auth/reset-password` | 持有有效恢复链接的用户 |
| Auth 回调 | `/auth/callback` | Supabase 回调专用 |
| 账户中心 | `/account` | 已登录用户 |

受保护路由至少包括 `/create`、`/icons`、`/icons/[jobId]`、`/account` 和支付发起接口。

## 5. 登录与账户功能需求

### AUTH-001 邮箱注册 — P0

用户输入邮箱、密码并同意服务条款和隐私政策后创建账户。

业务规则：

- 邮箱去除首尾空格并按不区分大小写处理。
- 密码至少 8 个字符；具体复杂度由 Supabase Auth 策略统一控制。
- 条款与隐私政策必须主动勾选。
- 注册成功后进入邮箱验证提示页。
- 不通过响应暴露某邮箱是否已注册的敏感细节。

验收标准：

- 合法信息能够建立 Auth 用户、`profiles` 和 `credit_accounts` 记录。
- 注册成功会发送验证邮件。
- 重复提交不会建立重复资料或余额账户。
- 校验失败时保留邮箱输入，但不保留密码。

### AUTH-002 邮箱验证 — P0

用户点击验证邮件链接后完成邮箱验证。

业务规则：

- 回调地址必须属于允许的站点域名。
- 验证成功后跳转原目标地址，缺失时跳转 `/create`。
- 链接无效或过期时允许重新发送验证邮件。
- 重发邮件必须限流。

验收标准：

- 有效链接可以完成验证并建立会话。
- 无效链接显示明确错误，不进入受保护业务。
- 已验证用户重复打开链接不会破坏账户状态。

### AUTH-003 邮箱密码登录 — P0

用户使用邮箱和密码登录。

业务规则：

- 登录成功后优先返回登录前目标地址。
- 未验证邮箱进入验证提示流程。
- 错误信息统一为英文，不明确指出邮箱或密码哪一项错误。
- 连续失败需要由 Supabase 和应用层限流。

验收标准：

- 正确凭据建立安全会话。
- 错误凭据不建立会话。
- 已登录用户访问登录页会跳转到 `/create`。

### AUTH-004 会话保持 — P0

用户刷新页面或重新打开站点后，在有效期内保持登录状态。

业务规则：

- 使用 Supabase 服务端 Cookie 会话。
- 服务端渲染和 Route Handler 必须独立校验会话，不信任前端状态。
- 会话过期时清理本地状态并跳转登录页。
- 登录跳转参数只能是站内安全路径，防止开放重定向。

验收标准：

- 刷新受保护页面不会错误退出。
- 无效 Cookie 无法访问用户数据接口。
- 用户 A 的会话不能读取用户 B 的资源。

### AUTH-005 受保护页面拦截 — P0

未登录用户访问受保护页面时跳转登录页，并记录原目标路径。

验收标准：

- 登录后能够回到原目标路径。
- 未验证或受限制用户只能访问其允许页面。
- API 返回 `401` 或 `403`，不能返回 HTML 登录页面。

### AUTH-006 退出登录 — P0

用户可以从应用导航或账户页退出。

验收标准：

- 退出后服务端会话被清除。
- 浏览器后退不能继续访问需要服务端数据的页面。
- 退出后跳转首页或登录页。

### AUTH-007 忘记与重置密码 — P0

用户提交邮箱获取密码恢复链接，并在有效回调中设置新密码。

业务规则：

- 忘记密码响应不透露邮箱是否存在。
- 重置链接必须有有效期并只能按 Supabase 策略使用。
- 新密码必须满足当前密码策略。
- 重置成功后清理恢复状态并跳转登录页或账户页。

验收标准：

- 有效恢复链接可以设置新密码。
- 无效或过期链接显示重新申请入口。
- 旧密码不能在重置后继续登录。

### AUTH-008 登录安全与审计 — P1

系统记录必要的认证安全事件，但不得记录密码、Token 或完整 Cookie。


## 6. 用户信息功能需求

### USER-001 查看账户摘要 — P0

账户页展示：

- 登录邮箱。
- 邮箱验证状态。
- 昵称。
- 当前点数余额。
- 充值入口。

当前界面不展示账户创建时间、“账户正常”状态文案或生成统计；账户异常状态仍必须在需要阻止操作时给出明确提示。

验收标准：

- 数据来自当前服务端会话对应用户。
- 加载、空值和请求失败均有明确界面状态。
- 点数余额与数据库 `credit_accounts.balance` 一致。

### USER-002 修改昵称 — P0

用户可以新增或修改昵称。

业务规则：

- 去除首尾空格。
- 长度为 1–40 个字符；允许清空并恢复为未设置状态。
- 首版不要求昵称唯一。
- 更新成功后同步刷新页面账户信息和顶部导航用户名，不展示邮箱作为顶部用户名称。

验收标准：

- 用户只能修改自己的资料。
- 非法长度不会写入数据库。
- 成功与失败均有当前界面语言反馈。

### USER-003 查看点数余额 — P0

账户页展示当前点数余额；顶部导航不展示余额，避免导航拥挤。余额变化后账户页和需要报价的业务页面重新获取服务端数据。

业务规则：

- 余额只读，用户不能通过资料接口修改。
- 余额变化只能通过购买、生成扣点、失败退款或管理员调整产生。
- 新用户首次初始化时可通过“注册体验赠送”增加余额，并产生独立账本记录。
- 前端展示值不能作为生成权限的可信依据，创建任务时仍由数据库重新校验。

### USER-003A 新用户体验点数 — P0

新用户建立完整的 `profiles` 和 `credit_accounts` 记录后，由服务端一次性发放 6 点体验点数。

业务规则：

- 赠送数量首发配置为 6 点，前端不得提交或修改赠送数量。
- 同一 Auth 用户终身只发放一次；注册重试、邮箱验证回调和资料补偿任务不得重复发放。
- 发放与余额更新、账本写入在同一事务完成。
- 账本类型为 `signup_bonus`，记录配置版本和幂等业务键。
- 删除后重新注册、同邮箱重复注册等防滥用策略需要在上线前确认；MVP 至少按 Auth 用户 ID 保证幂等。
- 账户页和首次进入创建页时展示赠送成功、当前余额以及“可生成 6 个主体”的价格版本说明。

验收标准：

- 新用户完成账户初始化后能看到体验点数。
- 同一注册流程重复执行不会重复增加余额。
- 发放失败可由后台补偿任务安全重试。
- 前端无法通过修改请求参数增加赠送点数。

### USER-004 查看账户状态 — P1


- `active`：正常使用。
- `restricted`：禁止生成与支付，允许查看账户和联系支持。

该状态需要通过后续数据库迁移加入 `profiles`。



业务规则：

- 删除属于高风险操作，需要重新认证和二次确认。
- 确认文案明确说明作品、剩余点数及账号访问将受到影响。
- 存在 `queued` 或 `processing` 任务时暂不执行删除，并提示稍后重试。
- 删除申请成功后立即展示“下载我的数据”按钮，并注明宽限期截止时间。
- 删除宽限期为 30 天；期满后执行账户清理，旧会话失效。
- 实际删除由服务端管理权限执行，前端不得持有 Service Role Key。
- 订单、账本和审计数据的删除、保留或匿名化策略仍需在上线前单独确认。
- 删除动作必须写入审计日志。

验收标准：

- 未重新认证不能提交删除请求。
- 重复提交保持幂等，不创建多个删除任务。
- 用户不能删除其他账户。
- 删除申请成功后用户可以创建数据导出任务并下载 ZIP。
- 数据导出失败可以安全重试，不得延长作品原始保留期限。
- 删除完成后旧会话不能继续访问资源。

### USER-006 下载用户数据与资产 — P0


导出内容包括：

- 用户资料 `profile.json`：用户 ID、邮箱、显示名称、语言、账户状态和创建/更新时间。
- 点数账本 `credit-ledger.csv`：变动类型、点数变化、余额快照、关联任务/订单和时间。
- 账单摘要 `billing-summary.json`：累计购买金额与点数、累计使用/返还/调整点数、当前余额和统计区间。
- 图标任务清单和结构化设计设置 `manifest.json`。
- 仍在 30 天保留期内的母版及派生 PNG。


业务规则：

- 导出采用异步任务，状态为 `queued / processing / ready / failed / expired`。
- 导出 ZIP 保存 24 小时，使用短时签名 URL 下载；过期后用户可在删除宽限期内重新生成。
- 同一用户同时只运行一个导出任务，重复提交使用幂等键复用现有任务。
- 作品 30 天清理与数据导出均不在当前范围，后续重新立项时再定义相互影响。
- 只有账户本人能创建和下载导出；服务端必须重新校验会话和资源所有权。
- 账户正式删除前，系统应等待正在处理的数据导出结束或达到明确超时。

验收标准：

- ZIP 包含当前用户的资料、订单、完整点数账本、账单摘要和仍有效的作品资产，不能包含其他用户数据。
- 24 小时后下载链接失效，但宽限期内可以重新申请。
- 导出失败不影响删除申请状态，并提供可重试错误提示。

## 7. API 需求

### Supabase Auth 操作

注册、登录、验证、重发验证、忘记密码、重置密码和退出优先使用 Supabase Auth SDK，并通过服务端 Cookie 集成。

### GET `/api/account`

返回当前账户摘要。

响应示例：

```json
{
  "id": "user-uuid",
  "email": "user@example.com",
  "emailVerified": true,
  "displayName": "Alex",
  "creditBalance": 20,
  "status": "active",
  "createdAt": "2026-08-19T10:00:00.000Z"
}
```

错误：`401 AUTH_REQUIRED`、`500 ACCOUNT_LOAD_FAILED`。

### PATCH `/api/account/profile`

请求：

```json
{
  "displayName": "Alex"
}
```

错误：`400 VALIDATION_ERROR`、`401 AUTH_REQUIRED`、`500 PROFILE_UPDATE_FAILED`。


请求：

```json
{
  "confirmation": "DELETE",
  "password": "current account password",
  "idempotencyKey": "uuid"
}
```

错误：`400 INVALID_CONFIRMATION`、`401 REAUTH_REQUIRED`、`409 ACTIVE_GENERATION_EXISTS`、`409 DELETION_ALREADY_PENDING`。

### POST `/api/account/data-export`


请求：

```json
{
  "idempotencyKey": "uuid"
}
```

响应：

```json
{
  "exportId": "export-uuid",
  "status": "queued",
  "deletionScheduledAt": "2026-09-19T10:00:00.000Z"
}
```

### GET `/api/account/data-export/{exportId}`

返回导出状态；`ready` 时返回短时 `downloadUrl` 和 `expiresAt`。

错误：`401 AUTH_REQUIRED`、`403 RESOURCE_FORBIDDEN`、`409 EXPORT_ALREADY_RUNNING`、`410 EXPORT_EXPIRED`、`500 EXPORT_FAILED`。

## 8. 数据需求

已有数据：

- `auth.users`：认证身份、邮箱和验证状态。
- `profiles`：邮箱快照、昵称和创建时间。
- `credit_accounts`：当前点数余额。
- `admin_audit_logs`：管理和敏感操作审计。

待增加字段或表：

- `profiles.updated_at` 自动更新时间。
- `account_data_exports`：导出状态、对象路径、清单哈希、创建/完成/过期时间、幂等键和失败原因。

所有用户表必须启用 RLS。用户只能读取或更新允许的自身字段，Service Role 仅用于服务端管理操作。

## 9. 错误与界面文案原则

- 所有面向海外用户的文案首版使用英文。
- 表单错误显示在对应字段附近，页面级错误使用统一提示组件。
- 登录错误不泄露账户是否存在。
- 网络错误提供重试入口，不自动重复提交高风险操作。

## 10. 埋点与指标

建议事件：

- `sign_up_started`、`sign_up_completed`
- `email_verification_completed`、`verification_resend_requested`
- `sign_in_completed`、`sign_in_failed`
- `password_reset_requested`、`password_reset_completed`
- `profile_updated`


## 11. 非功能要求

- 认证和账户接口必须使用 HTTPS。
- 服务端鉴权失败默认拒绝访问。
- 表单支持键盘操作、明确 Label、错误关联和焦点管理。
- 账户页移动端和桌面端均可使用。
- 关键认证页面应避免泄露用户专属数据到共享缓存。
- API 使用稳定错误码，前端不依赖供应商原始错误文本。

## 12. MVP 不包含

- Google、Apple、GitHub 等社交登录。
- Magic Link 登录。
- 多因素认证。
- 用户自行修改邮箱。
- 多团队或组织账户。
- 用户头像上传。
- 多语言账户邮件和页面。

## 13. 与新版生成闭环的联动

- 账户页的使用统计以批量任务、图标主体和成功 variant 分开计数，不再把一张结果等同于一次任务。
- 点数余额变化后，App Shell、创建页报价、账户摘要和支付结果页需要重新拉取服务端余额。
- 语言偏好只影响显示文案，不改变核心设置稳定 ID、用户主体原文或 Skill 运行配置。

## 14. 模块完成定义

两个模块必须同时满足以下条件才算完成：

- P0 页面和接口全部实现。
- 受保护路由和 RLS 权限测试通过。
- 注册、验证、登录、重置密码、退出和账户资料流程通过端到端测试。
- 不存在前端 Service Role Key 或密钥泄漏。
- 英文邮件模板和生产回调域名已配置。
- 错误状态、加载状态和移动端布局完成。
