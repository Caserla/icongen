# 透明背景生成提示词

本地提示词版本：`0.10.3`。本次没有部署线上服务。

## 请求模式隔离（0.10.3）

- 新建图标和生成重试固定调用 `POST /v1/images/generations`。本地 Sub2API 将这个入口映射为图像工具的 `action: "generate"`。
- 不再因存在风格参考图自动调用 `/images/edits`；新建请求只发送文字，不上传参考图或源图，不带 `input_fidelity`，也不追加“附带参考图”的提示。
- 九种风格继续使用编译后的风格文字规则。参考图仍可用于本地质量检查，但不再作为新建生图的上游图片输入；视觉一致性需要另行实测。
- 只有 `mode: "detail-edit"` 才调用 `/images/edits`（`action: "edit"`），且必须提供源图。缺少源图时在请求前报错，不能悄悄变成新建生图。
- 使用本机模拟 HTTP 服务检查 SDK 的实际请求路径、JSON/multipart 内容和返回值；34 项相关测试和 icon-skill/icon-worker 类型检查通过。没有为路由验证调用付费上游，也没有修改或部署 Sub2API。

## 新建生成与重试

- 仅在有效背景设置为关闭（界面选择透明背景）时，九种插画风格使用独立前景任务描述。主体的独立背景设置优先于全局设置。选择纯色或渐变时仍使用原背景与容器规则。
- 任务开头直接要求：只生成指定物品主体及其必要组成部分，不生成背景、周围场景、地面或展示平面。
- Provider 发出请求前追加一次简短的真实透明 PNG 输出要求，放在主体、风格参考和重试纠正之后。原文见 `services/icon-worker/src/adapters/openai-image-provider.ts` 的 `GENERATION_TRANSPARENCY_REQUIREMENT`。不再写入 PNG 编码类型、Alpha 数值及交替方块等图案枚举。
- 只让主体之外及真实空隙透明。实体表面保持不透明，按明确要求保留半透明材质。深色零件、内壁、凹陷和主体自身阴影属于主体，不因颜色深而透明。
- 光滑轮廓保留自然边缘覆盖，像素风保留硬像素边缘并去掉抗锯齿冲突，贴纸保留有意设计的描边，霓虹保留紧贴主体的光效。
- 透明分支不上传风格参考附件，也不注入参考图背景色的文字描述。内置风格文字提供形状、材质及边缘语言；用户主体描述控制内容、配色、相机及位置。
- 透明分支移除通用正面视角、强制方形居中及等距网格描述，尊重用户的主体构图。
- 质量重试继续要求真实 Alpha，不再自动改为绿幕或执行色键抠图。接口明确报错时直接报告，不把错误转换成另一条抠图链路。

## 兼容性与验收

网关请求继续省略原生 `background: "transparent"` 参数。代码中的 `native-alpha` 是提示词策略名称，不代表已经确认网关支持原生透明参数。

真实 Alpha、不透明外围和假透明网格只记录质量警告，不阻止生成结果展示。只有启用背景且容器为圆角方块或方块时才要求生成源图为方形；圆形背景和透明背景不检查方形尺寸。错误复制完整风格参考板仍会阻止交付。细节编辑的既有策略不在本次修改范围。
