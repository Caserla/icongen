# UI 与图片加载回归（2026-09-04）

## 范围

本轮覆盖创建页、我的图标列表、图标详情和细节调整之间的真实交互与资产加载路径，目标是消除筛选长时间骨架、已加载图片重复请求、旧加载文案和新旧视觉状态混用。

## 已落地变更

| 模块 | 问题 | 处理 | 验收标准 |
| --- | --- | --- | --- |
| 我的图标列表 | 切换风格后列表长期保持骨架，标题与卡片迟迟不出现 | 筛选状态驱动同一客户端列表实例；请求按当前页和筛选缓存；列表读取批量查询、优先 256px 缩略图并按 Bucket 批量签名 | 切换不卸载整页，不闪空状态；旧响应不能覆盖新筛选 |
| 列表数据库读取 | 多次数据库往返放大远程延迟 | 增加安全调用者权限的 `list_generation_jobs_v1` RPC，使用环境开关渐进启用，保留原链路回退 | RPC 始终按 `auth.uid()` 隔离；分页、用途、风格、结构和状态结果一致 |
| 图标详情 | 路由骨架后出现“正在加载生成详情”，图片再次缓慢请求 | 客户端加载器持续展示统一详情骨架；复用列表会话图片；详情资产优先返回直接签名 URL | 不显示可见加载文案；缓存图片先显示；无逐图代理 N+1 |
| 细节调整 | 已在详情加载的原图仍被骨架覆盖，接口返回后又换 URL | 打开编辑立即使用 `variant.previewUrl` 并 eager 加载；仅在本地没有 URL 时接受状态接口 URL | 原图不等待额度/草稿请求；同一资产不因重新签名闪烁 |
| 图片容错 | 内部代理 URL 可能携带错误 Origin，失败后没有刷新机会 | 内部生成资产统一归一化为当前 Origin，并保留一次刷新重试 | 签名/代理失败单图隔离，不阻断其他卡片 |
| 创建页主体输入 | 单行输入空间不足，多主体操作不顺畅 | 摘要输入点击后打开固定宽度多行浮层；新增/点击自动滚动定位；空值回显提示 | 浮层不改变原列表宽度，不被“添加主体”遮挡，200 字限制有效 |
| 加载与视觉 | 详情标题、预览尺寸、卡片入场和骨架样式不统一 | 标题改为“图标详情”；标题栏左右布局；预览弹层缩至 680px / 78vh；侧栏使用独立入场动画 | 不影响图标背景抽屉层级；支持 reduced motion |

## 自动化结果

- Web TypeScript：通过。
- Web 测试：73/73 通过。
- 重点断言包含缩略图尺寸选择、筛选状态保持、列表加载骨架、签名 URL 保持、修订发布后的 URL 更新和单图失败处理。

## 部署注意

1. 部署 `0027_generation_job_list_rpc.sql` 后再设置 `GENERATION_LIST_RPC_ENABLED=1`。
2. 未启用 RPC 时仍使用兼容读取链路，不影响上线。
3. 列表响应缓存位于单 Web 进程内，只作为短期性能优化，不作为业务状态来源；生成中状态 TTL 为 5 秒。
4. 签名 URL 缓存有数量上限和过期时间，详情与列表共享，但任何鉴权和所有权判断仍在数据查询阶段完成。
