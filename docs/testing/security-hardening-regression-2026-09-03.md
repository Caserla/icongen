# 安全加固回归测试与性能审查（2026-09-03）

## 1. 测试范围与原则

本轮覆盖提交 `e55b6d6`（生成运行时与生产运维安全加固）和 `656c5f2`（列表预览签名兼容修复）可能影响的前端、API、Worker、数据库迁移与部署配置。

测试分为四层：

1. 静态质量门：依赖审计、单元测试、类型检查、Lint、生产构建。
2. 安全边界：未认证访问、跨站写请求、Content-Type、健康检查鉴权、日志脱敏。
3. 真实登录态交互：图标列表、筛选、预览、结果页、细节调整入口、返回状态与下载请求。
4. 生产运行保障：迁移状态、Worker 租约、成本熔断、容器配置、备份与恢复脚本。

不会在回归中自动提交新的 Image2 生成或细节调整任务，避免消耗真实点数和模型费用；此类破坏性/计费型用例应在隔离验收账户中执行。

## 3. 建议补充的生产验收用例

### P0：上线前必须完成

1. **成本熔断启用**：配置用户日限额、全局并发、日/月主体限额，开启 enforcement；分别验证临界值内成功、越界返回稳定错误码、跨日/月恢复。
2. **数据库授权回归**：使用账户 A/B 创建独立数据；验证 A 无法读取 B 的 job、asset、revision，无法通过预览和下载接口枚举 B 的 UUID。
3. **Worker 故障接管**：两个 Worker 并发抢同一任务只允许一个成功；强制终止持锁 Worker，租约到期后另一个 Worker 接管；旧 Worker 恢复后不得覆盖新结果。
4. **真实恢复演练**：从加密备份恢复到空白实例，核对迁移版本、用户、点数账本、任务与 Storage 引用，记录 RPO/RTO。
5. **下载验收**：在普通 Chrome/Safari 下载单方案和多方案 ZIP；核对原图、全部 PNG 尺寸、可选 SVG、文件名、透明通道与总大小限制。

### P1：发布前推荐完成

1. 真实计费账户跑一项生成成功、失败返还、免费重试和单方案 3 次免费细节调整的端到端账本核对。
2. 让任务分别停留在 queued、processing、partial、failed，刷新和返回页面，确认状态不会回退或重复扣费。
3. 对包含透明图的生成与细节调整执行像素边缘检测，确认无黑角、白边、绿边和假棋盘格。
4. 对 401、403、409、413、429、500/503 做中英文前端提示验收，确保不暴露内部 Prompt、模型响应或 Storage 路径。

## 4. 前后端性能与交互审查

### 4.1 可直接优化（不改变业务规则）

1. **消除筛选请求重复发送（已完成）**：`IconJobList` 已改为 URL 单一请求源，点击处理器不再直接重复调用 `loadList`。
2. **取消旧请求（已完成）**：保留响应序列保护并增加 `AbortController`，切换时主动终止上一条筛选请求。
3. **列表查询减少数据量（已完成第一阶段）**：资产查询按 preview→source→最大 output 逐级回退，每个方案只读取一个优先资产，不再读取全部 PNG 尺寸。后续仍可使用受控 RPC/view 合并 jobs、subjects、variants 的往返。
4. **拆分“数据授权”和“Storage 签名”（已完成）**：列表、summary 与详情数据使用用户 session/RLS，独立 signer 只处理查询结果中已验证归属的路径。
5. **结果页只签首屏必需资源（已完成）**：详情 reader 只签每个方案的展示图和可选 SVG；各 PNG 尺寸保留元数据，下载时再由服务端读取。
6. **签名 URL 与图片缓存**：页面数据当前 `private, no-store`，但已完成项目在 1 小时内基本不变。可返回稳定的第一方 asset URL，并让该路由做短时 private cache/ETag；发布细节调整后只刷新对应 variant。
7. **ZIP 改为流式或异步产物**：下载接口当前把最多 64 MiB 输入全部读入内存后由 JSZip 打包。单机并发下载时会放大内存和事件循环压力。建议中等文件流式 ZIP，大包异步生成到私有 Storage 后发短期下载链接。
8. **明确首屏与折叠区图片策略**：真实快速切换后首屏图片已完成，折叠区图片保持浏览器 lazy pending。当前行为节省带宽但会让向下滚动时继续出现骨架；若产品要求整页一次完成，可在列表数据完成后做限并发预加载，并在所有图片 settled 后整体 reveal，代价是首屏更慢。建议保留首屏优先，提前预取下一屏，而不是一次加载全页。

### 4.2 需要生产环境配合

1. **分布式限流**：当前进程内限流在多实例、重启后不共享。生产应迁移到 Redis/Upstash 或数据库原子限流，并只信任来自受控反向代理的真实客户端 IP 头。
2. **慢查询和签名可观测性**：记录 list、details、download、Worker claim 的 p50/p95/p99、数据库耗时、签名耗时、返回字节数，不记录 Prompt 或 token。
3. **索引验证**：用生产规模数据执行 `EXPLAIN (ANALYZE, BUFFERS)`，重点检查 `generation_spec` JSON 路径筛选、`user_id + created_at`、status、subject/job、variant/subject 与 asset/variant 索引。
4. **CDN/图片派生**：列表只传 128/256 预览，不下载 512 原图；配置私有 CDN 或 Supabase 图片转换并保持 Alpha，减少带宽与解码开销。

## 5. 当前上线结论

代码级安全回归通过，登录态核心只读链路未被安全改动破坏。当前仍有三个明确的生产阻断项：运行时成本熔断尚未开启、跨账户 RLS/资源枚举尚未用双账户验收、备份恢复与双 Worker 接管尚未在隔离环境实测。完成这些项目后才能把“基本闭环”提升为“生产级闭环”。
