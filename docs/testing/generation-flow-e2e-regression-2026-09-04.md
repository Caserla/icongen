## 7. 三项缺口修复与复验（追加）

### 7.1 Filled + Transparent

根因不是提示词，而是当前模型网关在原生透明请求阶段直接返回 `400 Transparent background is not supported for this model.`，原逻辑只处理“已经返回图片但透明质量不合格”，因此没有机会进入质量重试。

修复后的策略：优先原生 Alpha；只对明确的“不支持透明参数”错误切换为色键工作底；将边缘连通的色键背景转换为真实 Alpha；清理边缘溢色；重新执行透明边界质量门禁。限流、余额、鉴权等其他错误不会被降级逻辑吞掉。

真实复验 Job `fda5d94c-f4e7-48da-bce3-a5d0da249450`：Filled + Transparent 三个方案全部完成。三个 512px PNG 均为 RGBA，完全透明像素比例分别约 71.33%、73.25%、71.38%。

### 7.2 主体透明度

`subjectOpacityPercent` 已加入版本化共享 Schema（0–100，旧任务默认 100）、创建请求、任务 JSON 快照、内置提示词和透明背景图片后处理。真实 Job 的持久化值为 45；三个原始 PNG 的最大 Alpha 均为 115（`round(255 × 45%)`），证明不是只改前端预览。

### 7.3 付费调整失败返还

故障注入要求同时满足：非生产环境、显式开关为 `1`、目标 Revision ID 完全匹配；生产环境即使误设变量也不会触发。

真实 Revision `2f1391e0-ccc0-41b2-9345-30ca122e1fd8`：余额 99 → 98（创建并扣款）→ 99（Worker 失败自动退款）；存在一条 `variant-edit-debit` 和一条 `variant-edit-refund`；重复执行退款余额仍为 99；浏览器重新进入调整页可见 `Detail adjustment failed`。
